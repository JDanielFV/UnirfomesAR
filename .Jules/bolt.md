## 2025-05-25 - React.lazy vs IntersectionObserver for lazy loading
**Learning:** React.lazy + Suspense natively defer component script fetching, but using them indiscriminately on an initial view triggers immediate parallel fetching of all lazy chunks because React still mounts them into the render tree immediately (behind the Suspense boundary). To genuinely prevent the browser from requesting the chunks/images until they are near the viewport, you must wrap them in an `IntersectionObserver` based conditional render mechanism (like a `LazySection` wrapper). Also, ensure `LazySection` wrappers are nested *inside* the outer elements carrying `id` attributes that anchor links target, otherwise single-page navigation will break because the target element doesn't exist in the DOM until scrolled to.
**Action:** When lazy-loading below-the-fold components, conditionally render the `Suspense` boundary using an `IntersectionObserver` instead of just using `React.lazy` unconditionally. Always preserve structural `<section id="target">` wrappers in the main App layout to maintain smooth scrolling capability. Provide a `minHeight` to the lazy fallback to prevent CLS.
