## Palette's Journal\n\n## 2025-02-12 - Replacing div buttons with semantic button elements for toggles\n**Learning:** Found a common pattern where a mobile menu toggle (`<MenuIcon>`) was implemented as a `styled.div` instead of a `styled.button`. While `cursor: pointer` handles mouse users, this approach completely breaks keyboard accessibility since `div`s are not focusable by default and screen readers cannot identify them as interactive controls. \n**Action:** When creating toggle icons (like hamburger menus), always use semantic `styled.button` components with appropriate ARIA attributes (`aria-label`, `aria-expanded`, `aria-controls`) and apply CSS resets (`background: none; border: none; padding: 0; outline: none;`) to achieve the desired visual style without sacrificing accessibility.

## 2025-02-12 - Adding accessibility to custom modals
**Learning:** Custom modals implemented purely with styled-components often miss critical accessibility and UX features such as ARIA roles, labels, 'Escape' key bindings, and click-to-close overlay behaviors, which makes them difficult to navigate via keyboard or assistive technologies. Using lazy loading (`loading="lazy"`) for images hidden in such modals prevents massive unnecessary network requests until the modal opens.
**Action:** Always include semantic attributes (`role="dialog"`, `aria-modal="true"`, `aria-label`) to custom modal content wrappers. Additionally, attach `useEffect` event listeners for the 'Escape' key and implement secure `e.target === e.currentTarget` checks on overlays to support intuitive click-to-close behavior. Apply `loading="lazy"` to images conditionally rendered inside modals.
