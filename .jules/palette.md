## Palette's Journal\n\n## 2025-02-12 - Replacing div buttons with semantic button elements for toggles\n**Learning:** Found a common pattern where a mobile menu toggle (`<MenuIcon>`) was implemented as a `styled.div` instead of a `styled.button`. While `cursor: pointer` handles mouse users, this approach completely breaks keyboard accessibility since `div`s are not focusable by default and screen readers cannot identify them as interactive controls. \n**Action:** When creating toggle icons (like hamburger menus), always use semantic `styled.button` components with appropriate ARIA attributes (`aria-label`, `aria-expanded`, `aria-controls`) and apply CSS resets (`background: none; border: none; padding: 0; outline: none;`) to achieve the desired visual style without sacrificing accessibility.

## 2025-05-16 - Adding keyboard accessibility to non-semantic navigation elements
**Learning:** Found that custom navigation elements (like `styled.img` and `styled.li`) used for page scroll navigation lack keyboard support by default. While mouse users can click them easily via `onClick`, keyboard users are entirely blocked as these elements aren't natively focusable and don't respond to 'Enter' or 'Space' events.
**Action:** Always provide explicit keyboard support to non-semantic elements used for navigation. Add `role="button"`, `tabIndex={0}`, and an `onKeyDown` event listener that explicitly calls `e.preventDefault()` (to prevent unintended page scrolling when 'Space' is pressed) before triggering the desired action.

## 2025-05-29 - Accessible and user-friendly custom modals
**Learning:** Custom modals (like `<ModalGallery>`) require explicit keyboard and pointer event handling for proper UX and accessibility. Without a global 'Escape' key listener, keyboard users are trapped. Without outside click handling on the overlay container (`e.target === e.currentTarget`), mouse users lack a common interaction pattern. Additionally, missing `role="dialog"` and `aria-modal="true"` prevents screen readers from understanding the context context.
**Action:** Always implement `useEffect` for 'Escape' key listeners (with cleanup), check `e.target === e.currentTarget` on the overlay for outside clicks, and apply semantic attributes (`role="dialog"`, `aria-modal="true"`, and `aria-label` for close buttons) on custom modal overlays.
