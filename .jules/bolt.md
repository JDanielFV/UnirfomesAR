## 2024-06-10 - Conditional IntersectionObserver vs Grouped Suspense Boundary
**Learning:** While `React.lazy` and `Suspense` can split bundles for below-the-fold components, placing them inside a single, unconditional `<Suspense>` boundary in `App.jsx` still triggers immediate network fetches for all lazy chunks on initial load. To truly defer loading until components enter the viewport and prevent waterfall blocking, they must be conditionally rendered using an Intersection Observer (e.g., a `LazySection` wrapper). Furthermore, to prevent cumulative layout shifts (CLS) when conditionally mounting these wrappers, a persistent `minHeight` must be set and maintained on the wrapper rather than removed upon intersection. Additionally, ensuring the `LazySection` wrapper is placed inside the `<section id="...">` rather than wrapping it is vital so that anchor links targeting those IDs are available in the DOM immediately.
**Action:** When implementing lazy loading for structural page sections, use a custom wrapper with `IntersectionObserver` that conditionally mounts children within their own `<Suspense>` boundaries. Ensure the wrapper maintains a `minHeight` permanently to avoid CLS, and ensure the wrapper is placed *inside* structural ID elements to preserve single-page navigation via anchor links.
