## 2024-06-12 - Implement IntersectionObserver for Lazy Component Rendering
**Learning:** While `React.lazy` and `Suspense` are great for code splitting, unconditionally wrapping components triggers network fetches instantly on page load, which acts like a waterfall request block for the user's initial load. To truly defer loading, rendering the child component must be conditional upon viewport entry (via `IntersectionObserver`). Furthermore, when doing this within sections tied to anchor links, the lazy wrapper must be inside the element providing the `id` attr; otherwise, wrapping the outer element removes the anchor from the DOM prior to scroll and breaks single-page navigation. Always specify a constant `minHeight` on the container to prevent a sudden layout collapse when loading the component, and preserve it permanently, rather than clearing it on load.
**Action:** When implementing lazy loading wrappers (`LazySection`) with `IntersectionObserver` and `React.lazy`, conditionally wrap `<Suspense>` within the intersection check. Also, place the wrapper *inside* the structural element bearing the `id` attribute to ensure anchor linking functions correctly, and maintain a consistent fallback `minHeight` throughout the loading and resolved state to completely avoid Cumulative Layout Shift (CLS) regressions.
